# LuxuryStay HMS MongoDB Setup

This guide configures the existing LuxuryStay HMS project without deleting existing data.

## What the Terms Mean

- **MongoDB**: The database used to store users, rooms, bookings, invoices, reports, and settings.
- **MongoDB Atlas**: MongoDB's hosted cloud service.
- **Cluster**: The hosted MongoDB deployment that runs your database.
- **Database**: A named collection of application data, such as `luxurystay`.
- **Collection**: A group of related records, similar to a table. Examples include `users` and `rooms`.
- **Document**: One MongoDB record, similar to a row.
- **Connection string**: The private URL the backend uses to connect to MongoDB.
- **Database user**: The Atlas username/password allowed to connect to the cluster. This is separate from hotel login accounts.

## A. Create an Atlas Database

1. Open MongoDB Atlas and create an account.
2. Create a project and a free or development cluster.
3. Open **Database Access** and create a database user.
4. Open **Network Access** and add your current IP address. For temporary local testing, Atlas also offers `0.0.0.0/0`, but a specific IP is safer.
5. Open the cluster's **Connect** menu and copy the Node.js connection string.

## B. Configure the Backend Locally

Edit this file locally:

`server/.env`

Use this shape and replace the placeholders locally. Do not commit this file or paste its secrets into chat:

```env
PORT=5000
MONGO_URI=mongodb+srv://<atlas-user>:<atlas-password>@<cluster-host>/luxurystay?retryWrites=true&w=majority
MONGODB_URI=mongodb+srv://<atlas-user>:<atlas-password>@<cluster-host>/luxurystay?retryWrites=true&w=majority
JWT_SECRET=<long-random-local-secret>
```

If the Atlas password contains characters such as `@`, `:`, `/`, or `#`, URL-encode the password inside the connection string. Keep `JWT_SECRET` private and do not expose `.env` through the client.

## H. Find Data in Atlas

1. Open the Atlas project and select the cluster.
2. Click **Browse Collections**.
3. Select the `luxurystay` database, or the database name at the end of your connection string.
4. Inspect the collections generated by the Mongoose models. Typical names are:
   - `users`
   - `rooms`
   - `roomtypes`
   - `bookings`
   - `housekeepingreports`
   - `housekeepingtasks`
   - `maintenancerequests`
   - `invoices`
   - `servicerequests`
   - `notifications`
   - `feedbacks`
   - `settings`

Use the **Documents** tab to inspect records. Do not edit production records in Atlas unless you understand the workflow.

## I. Backup and Restore

For a local MongoDB installation, create a backup with:

```powershell
mongodump --uri="mongodb://127.0.0.1:27017/luxurystay" --out=".\backups\luxurystay-backup"
```

Restore it with:

```powershell
mongorestore --uri="mongodb://127.0.0.1:27017/luxurystay" .\backups\luxurystay-backup\luxurystay
```

For Atlas, use Atlas's scheduled backup feature when available, or run `mongodump` with the private Atlas connection string from a protected deployment environment.

## J. Troubleshooting

- **Database service unavailable**: Check `MONGO_URI`, Atlas Network Access, database credentials, and whether the backend is running.
- **`Unexpected token '<'`**: The browser received an HTML page instead of an API response. Confirm the backend is running on port 5000, the Vite proxy is active on port 3000, and restart stale Node/Vite processes after code changes.
- **Port already in use**: Stop the old process using port 5000 or 3000 before starting another copy. Do not run multiple backend copies against the same port.
- **Authentication failure after reseeding**: Run `npm run seed` against the same MongoDB URI used by the backend, then restart the backend.
